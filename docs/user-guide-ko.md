# DataFixer 사용자 가이드 — V1 + 승인된 시장 확장

## DataFixer란?
DataFixer는 CSV와 Excel(XLSX) 파일을 이 브라우저 안에서 정리(Clean), 통합(Merge), 정확 조회(Lookup), 검증(Validate)하는 로컬 우선 도구입니다. 파일 내용은 처리 과정에서 외부 서버로 업로드하지 않으며 원본 파일을 덮어쓰지 않습니다.

## 지원 파일과 제한
- 입력: CSV(UTF-8 / UTF-8 BOM), XLSX
- 파일당 최대 20MiB
- 한 작업의 총 파일 크기 최대 50MiB
- 한 작업당 최대 10개 파일
- Chrome, Edge, Firefox 최신 버전이 V1 검수 대상입니다.
- Safari는 V1 공식 지원 대상이 아닙니다.

## 기본 사용 순서
1. Clean / Merge / Lookup / Validate 중 작업을 선택합니다.
2. 파일을 선택합니다. Merge는 여러 파일, Lookup은 정확히 2개 파일(첫 번째=기준, 두 번째=참고)을 사용합니다.
3. XLSX는 사용할 워크시트를 선택합니다.
4. 규칙, Merge 열 매핑 또는 Lookup 키/가져올 열을 설정하거나 기존 설정 JSON을 불러옵니다.
5. 시험 실행을 눌러 최대 첫 200개 데이터 행의 예상 결과를 확인합니다.
6. 전체 행 처리를 눌러 전체 작업을 실행합니다.
7. 결과 요약과 행 수 검증 상태를 확인한 뒤 결과물을 다운로드합니다.

## Clean
공백 제거, 연속 공백 축소, 빈 값 통일, 대소문자 변환, 날짜/숫자 정규화, 일반 찾기/바꾸기, 정규식 패턴 찾아 바꾸기, 빈 값 기본값 채우기, 여러 열 중 첫 유효값으로 채우기, 열 이름 변경, 열 선택, 중복 제거를 규칙 순서대로 실행합니다. 잘못된 날짜나 숫자를 임의 변환하지 않고 해당 행을 `REJECTED`로 분리합니다. 패턴 찾아 바꾸기 예: 전화번호 `(010) 1234-5678`에서 `[^0-9]+`를 빈 문자열로 바꾸면 `01012345678`이 됩니다. 새 패턴 규칙은 안전을 위해 빈 패턴으로 시작하며, 올바른 패턴을 입력하기 전에는 실행 전 검증에서 차단됩니다.

## Merge
파일별로 서로 다른 열 이름을 하나의 결과 열로 매핑합니다. 누락된 결과 열은 빈 값으로 채우고 필요하면 원본 파일명을 출처 열에 기록합니다. 중복 기준 열을 설정할 수 있으며 서로 충돌하는 자료형은 자동 변환하지 않고 원본 행을 보류합니다.

## Lookup
두 파일을 SKU, 고객 ID, 이메일 같은 **정확한 키**로 연결합니다. 첫 번째 파일이 기준 파일이고 두 번째 파일이 참고 파일입니다. 기준 키와 참고 키의 개수는 같아야 하며 복합키도 사용할 수 있습니다. 정확히 한 행이 일치하면 선택한 참고 열의 값을 새 결과 열에 추가합니다. 일치하는 참고 행이 없으면 `REJECTED`, 같은 키가 여러 참고 행에 있으면 자동으로 하나를 고르지 않고 `REJECTED`로 보류합니다. 숫자 `1`과 문자열 `"1"`은 서로 다른 키입니다. 가져온 값의 Evidence에는 어떤 참고 원본 행에서 왔는지도 기록됩니다.

## Validate
필수값, 자료형, 중복 금지, 허용값, 숫자 범위, 문자열 길이, 정규식, 두 열 비교를 검사합니다. 한 행이 여러 규칙에 실패하면 그 모든 이유를 기록하지만 오류 행 자체는 한 번만 계산합니다.

## 상태 의미
- `UNCHANGED`: 규칙 적용 후 값이나 구조가 바뀌지 않았습니다.
- `CHANGED`: 값, Merge 결과 구조 또는 Lookup으로 추가된 값이 변경되었습니다.
- `REMOVED`: 중복 제거 등 명시적 규칙으로 결과에서 제외되었습니다.
- `REJECTED`: 값 또는 자료형 문제 때문에 정상 결과에 포함할 수 없습니다.

항상 `입력 행 = UNCHANGED + CHANGED + REMOVED + REJECTED`가 성립해야 합니다. 성립하지 않으면 DataFixer는 결과를 정상 완료로 표시하지 않습니다.

## 다운로드 결과물
- 결과 XLSX: 정상 결과, 처리 근거, 요약
- 오류 XLSX: 오류/보류 행과 해당 행의 전체 처리 근거
- HTML 보고서: 처리 요약, 규칙별 근거, 입력/설정 해시
- 설정 JSON: 같은 규칙, Merge 매핑 또는 Lookup 설정을 다음 작업에서 재사용

DataFixer는 입력 파일과 같은 이름으로 원본을 덮어쓰지 않습니다.

## 자주 발생하는 오류
- `EMPTY_FILE`: 빈 파일입니다.
- `UNSUPPORTED_FILE`: CSV 또는 XLSX가 아닙니다.
- `FILE_TOO_LARGE`: 파일 하나가 20MiB를 초과합니다.
- `JOB_TOO_LARGE`: 선택한 파일 총합이 50MiB를 초과합니다.
- `TOO_MANY_FILES`: 파일이 10개를 초과합니다.
- `DUPLICATE_SOURCE_NAME`: 같은 파일명이 두 번 포함되었습니다.
- `MISSING_COLUMN`: 규칙이 존재하지 않는 열을 참조합니다.
- `INVALID_RULE`: 규칙, Merge 또는 Lookup 설정이 모순되거나 잘못되었습니다.
- `PARSE_FAILED`: 파일 또는 선택한 워크시트를 읽을 수 없습니다.
- `EXPORT_FAILED`: 결과 파일 생성에 실패했습니다.
- `RECONCILIATION_FAILED`: 행 수나 근거가 맞지 않아 안전하게 결과를 내보낼 수 없습니다.

## 개인정보와 보안
고객 파일의 바이트, 열 이름, 셀 값, 규칙 설정 및 처리 근거를 서버나 분석 도구로 보내지 않는 것이 V1 원칙입니다. 앱을 연 뒤 필요한 코드가 로드된 상태에서는 현재 작업을 오프라인에서도 계속 처리하도록 설계했습니다. 실제 배포 전에는 브라우저 네트워크 검수로 외부 전송 0건을 확인해야 합니다.
